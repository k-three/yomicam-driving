# 送迎記録アプリ（Web版・移行中）

Apps Script 版（リポジトリ直下の `Code.gs` / `Index.html`）を置き換えるための Web アプリ。
**移行が完了するまで Apps Script 版が本番**で、こちらは並行して開発する。

## なぜ移行するか

| 目的 | Apps Script 版の限界 | Web版でどうなるか |
|---|---|---|
| 運転手の負荷 | 電波が悪いと「未保存◯件」が残る | Firestore のオフライン保存で、圏外でも記録できる |
| 速度 | 全操作がスクリプト全体のロックで直列化。起動も iframe 経由で数秒 | ロック不要。PWA として端末にキャッシュされ即起動 |
| 報告書 | 印刷設定のAPIが無く、シートごとに5項目を毎回手で指定 | ボタン1つで A4横・体裁固定の PDF |
| 品質 | 開発側が実機で画面を確認できない | Playwright でブラウザを起動して確認できる |

## 構成

- Vite + TypeScript
- Firestore（オフライン永続化）／ Cloud Functions は使わない（無料枠のまま運用するため）
- 配信は **GitHub Pages**（虎の巻と同じ置き場所。無料）
- 権限：運転手と管理者を分離（下記）
- 帳票：ブラウザ内で PDF と Excel を生成
- デプロイ：GitHub Actions → GitHub Pages（鍵の設定は不要）

## 権限の分け方

運転手用と管理者用で**入口も権限も分ける**。パスワードが漏れても、確定した帳簿を
書き換えられない、という線を Firestore のルール（`firestore.rules`）で引く。

| | 入口 | 認証 | できること |
|---|---|---|---|
| 運転手 | `/` | パスワード |  記録の追加、**運行中**の記録の更新・リセット |
| 管理者 | `/admin.html` | パスワード |  すべての記録の修正・削除、マスタの変更、帳票の作成 |

どちらも**パスワードだけ**を入力する。Firebase の「メール/パスワード」認証は
メールアドレスを必要とするので、役割ごとに1つの形式的なアドレスを決め打ちにし
（`src/config.ts`）、画面では聞かない。個人別のアカウントは作らない。
誰が運転したかは、記録そのものの運転者欄が持つ。

- **パスワードは Firebase 側で照合される。** 画面のコードを読まれても突破できない。
  パスワードそのものはこのリポジトリに入っていない（Firebase 側に保管されている）。
  変えたいときはコンソールでそのユーザーのパスワードを変えるだけでよく、コードの修正は要らない。
- **匿名ログインは使わない。** セキュリティルールでも明示的に締め出してある
  （`sign_in_provider == 'password'`）ので、設定を取り違えて匿名を有効にしてしまっても
  記録は読めない。
- 管理者として中に入れるのは、さらに `admins` に自分の uid の文書がある人だけ。
  この文書の作成は Firebase コンソールからの手作業に限定してあり、
  **誰も自分で管理者に昇格できない**。
- 運転手のアカウントでは `/admin.html` に入れない（帳票も是正操作もできない）。
- 運転手が直せる・消せるのは**当日の記録だけ**。前日以前は読めるが触れない
  （`firestore.rules` の `isToday()`。記録が持つ `ymd` を、日本時間の今日と比べる）。
  打ち間違いや誤った記録はその場で消せて、月次で提出したあとの帳簿は動かない、という線。
- アルコールチェックは運行に紐づかない独立した法定記録なので、運行を消しても
  自動では消えない。ただしその運転者の当日の運行が1件も無くなる場合は、
  まとめて消すかどうかを尋ねる（`ui/remove.ts`）。

## コマンド

```bash
npm install
npm test        # 集計ロジックの検証
npm run dev     # 開発サーバー
npm run build   # 型チェック＋ビルド
npm run e2e     # ブラウザを起動して画面を確認（同梱の Chromium を使用）
npm run test:rules  # セキュリティルールの検証（Firestore エミュレータ。Java が要る）
```

**`firestore.rules` を変えたら、必ず `npm run test:rules` を通し、
コンソールから反映し直すこと。** ルールの反映だけは自動化していないので、
忘れると「画面はあるのに動かない」状態になる（実際に2度起きた）。

Firebase に触らずに画面だけ見たいときは `?mock=1` を付ける
（`/?mock=1`、`/admin.html?mock=1`）。自動テストもこれを使う。

## 動かすまでにやること

コードは書けているが、**下記が済むまで本番では動かない**。

1. **Authentication → Sign-in method** で「**メール / パスワード**」を有効にする。
   匿名は有効にしない（有効でもルール側で弾くが、そもそも要らない）。
2. **アカウントを2つ作る**
   Authentication → Users → ユーザーを追加。受信はしないので、
   実在のメールアドレスである必要はない。

   | 用途 | メールアドレス | パスワード |
   |---|---|---|
   | 運転手 | `driver@yomicam-driving.firebaseapp.com` | ここで決める |
   | 管理者 | `admin@yomicam-driving.firebaseapp.com` | ここで決める（運転手用とは別にする） |

   **パスワードはこのリポジトリに書かない。** 公開リポジトリなので、
   書けばそのまま公開され、履歴からも消せなくなる。

   アドレスは `src/config.ts` の `DRIVER_EMAIL` / `ADMIN_EMAIL` と一致させること。
3. **承認済みドメインを追加する**

   Authentication → Settings → 承認済みドメイン に `k-three.github.io` を追加。
   これが無いと、公開したページからログインできない。

4. **セキュリティルールを反映する**

   Firestore Database → **ルール** タブを開き、このリポジトリの
   `app/firestore.rules` の中身をそのまま貼り付けて「**公開**」。

   反映前は既定のルールのままで、権限の線が引かれていない。ここは必ず行う。
   （コンソールでの貼り付けを基本にしているのは、この手順のためだけに
   パソコンへ開発ツールを入れずに済ませるため。ルールを変えるのは稀。）

5. **GitHub Pages を有効にする**

   GitHub の Settings → **Pages** → Source を「**GitHub Actions**」にする。
   あとは `main` にコードが入るたびに、検査（型・集計・ブラウザ）が通ったものだけが
   自動で公開される。鍵や Secrets の設定は要らない。

   公開後のURLは次のとおり。

   | | URL |
   |---|---|
   | 運転手 | https://k-three.github.io/yomicam-driving/ |
   | 管理者 | https://k-three.github.io/yomicam-driving/admin.html |

6. **管理者を登録する**

   `https://k-three.github.io/yomicam-driving/admin.html` を開き、
   管理者用パスワードでログインする。まだ名簿に載っていないので
   「この画面を見る権限がありません」と出て、自分の ID（uid）が表示される。
   これをコピーして、コンソールで登録する。

   Firestore Database → データ → **コレクションを開始**
   - コレクションID … `admins`
   - ドキュメントID … コピーした uid をそのまま貼る
   - フィールド … 何も入れなくてよい

   保存したら再読み込みすると入れる。
   この登録はコンソールからしかできない（ルールで `write: false`）ので、
   **誰も自分で管理者になれない**。

7. **運転者・車両を登録する**

   管理画面を開くと「運転者と車両が仮の名前のままです」と案内が出るので、
   「**設定**」から実際の運転者名・車両名・自動車登録番号を入れて保存する。
   保存先は Firestore（`config/master`）で、リポジトリには残らない。
   登録すると案内は消える。

   自動車登録番号は、保険会社への輸送記録に出るので必ず入れる。
   空欄のままだと車両の呼び名がそのまま出力され、「要確認」に挙がる。

   **以後、職員や車両が増えたときも、ここから追加する。**
   コードの修正もデプロイも要らない。



## 通信が切れたときの動き

Firestore の端末内キャッシュを有効にしてあるので、**圏外でも記録は端末に残り、
電波が戻ると自動で送られる**。運転手アプリの上部に「未送信 N件」と出るのは
その状態を伝えるためで、操作は止めない。書き込みの完了を待たずに画面を進める
作りにしてあるのは、電波待ちで運転手を止めないため。

## 帳票

管理画面の「月次帳票」から、月を選んで出す。

| 帳票 | 提出先 | 向き |
|---|---|---|
| 輸送記録 | 保険会社（移動支援サービス専用自動車保険の月次通知） | 横（集計は縦） |
| アルコールチェック記録簿 | 安全運転管理者（保存義務1年） | 縦 |
| 運行日報 | 社内 | 横 |
| 要確認一覧 | 提出前の自己点検 | 横 |

出力は2通り。

- **印刷 / PDF** … ブラウザの印刷が開く。A4・余白10mm・向き・見出し行の
  ページごとの繰り返しまで指定済みなので、印刷設定をいじらずにそのまま出せる。
  送信先で「PDFに保存」を選べば PDF になる。PDF ライブラリを使っていないのは、
  日本語フォントの埋め込みで数MBになるうえ、ブラウザの印刷のほうが改ページを
  きれいに扱えるため。
- **Excel** … 列幅・見出しの書式・ウィンドウ枠の固定・印刷設定（A4・向き・
  横1ページに収める・見出し行の繰り返し）を入れた .xlsx を作る。
  書き出しは `src/export/xlsx.ts` の自前実装（zip 圧縮に fflate のみ使用）。

ダウンロードするファイル名は半角英数にしてある（例 `yomicam_insurance_202609.xlsx`）。
ブラウザによっては日本語のファイル名が落ちて「download」という名前で保存されて
しまうため。**シート名と表題は日本語のまま**なので、開けばどの帳票かは分かる。

## アルコールチェックの写真

対面で確認できないとき（自宅から出発するなど）、検知器のメーターを撮った写真を
記録に添付できる。運転手アプリの「0.00 以外・別の方法で記録」から。
管理画面では 📷 を押すと出る。

**Firebase Storage は使っていない。** 新しいプロジェクトでは Storage の利用開始時に
請求先（クレジットカード）の登録を求められる場合があり、無料のままを確実にするため。
代わりに、写真を縮めて Firestore に置いている。

- 長辺 1000px・JPEG 品質 0.6 に落とす。1枚おおむね 50〜150KB
- 画像は `alcoholPhotos/{記録のID}` に別置き。記録の一覧を開くたびに
  画像まで読み込まないようにするため。押したときだけ読む
- Firestore の無料枠は 1GiB。1日14枚・年間250日でも年 300MB 程度に収まるが、
  何年も貯めると効いてくる。アルコール記録簿の保存義務は1年なので、
  年に一度、古い写真を消す運用にするとよい

## 記録の直し方（管理者）

運行中の記録も確定済みの記録も同じ形（`Trip`）なので、同じ画面で直せる。

- **運行状況**タブ … 当日の運行とアルコールチェックを1件ずつ修正・削除、追記できる。
- **月次帳票**タブ … 要確認の各行に「直す」がつく。指摘から直接その記録を開ける。
- **設定** … 運転者・学校・拠点・確認者の一覧と、車両の自動車登録番号。

Apps Script 版では運行中の状態が別シートの状態JSONだったため手で直せず、
「おかしいと分かっても直せない」状態が起きていた。ここではそれが起きない。

## 残っている懸念

運転手も管理者もパスワード認証にしてあるので、**ログインできない人はデータを読めない**。
そのうえで残るのは次の3点。

- **パスワードの強さ。** 短く単純なものは総当たりに対して弱い部類。Firebase 側に
  自動のレート制限があり、画面にも「試行が多すぎます」を出しているが、
  長めのものにしたほうがよい。変更はコンソールでのパスワード変更だけで済み、
  コードの修正もデプロイも要らない。
- **運転手は1つのアカウントを共有する。** したがって `createdBy` は
  「誰が」ではなく「運転手アプリからか管理画面からか」を示す記録にとどまる。
  誰が運転したかは記録の運転者欄が持つ。退職などでパスワードを変えるときは
  全員へ配り直す必要がある。
- **このリポジトリは公開されている。** GitHub Pages を無料で使うための条件。
  したがって次を必ず守る。
  - パスワードを書かない（Firebase Authentication 側に置く）
  - 個人名を書かない（運転者・車両は管理画面の「設定」から登録し、Firestore に保存）
  - 運行の実データを置かない（すべて Firestore にある）

  公開されているのはアプリの**コード**であって、記録そのものではない。
  Firebase の設定値（`firebase-config.ts` の apiKey 等）は、ブラウザに配る前提で
  公開されるものなので、書いてあってよい。データを守るのはセキュリティルールと
  パスワードであって、この値を隠すことではない。

**アルコールチェックの数値は、運転手の画面では自分のぶんだけ出している。**
ただしこれは画面の作りによるもので、権限として遮っているわけではない。
運転手は全員が1つのアカウントを共有しているので、ルールで「本人のぶんだけ」を
表すことができない（誰であるかを Firestore 側が知らない）。
運行中の車両に「運転前チェックが未記録」を出すためにも、他の人の記録は必要になる。

数値そのものを他の運転手から遮りたい場合は、運転者ごとにアカウントを分ける必要がある。

さらに固めるなら **App Check（reCAPTCHA v3）** を有効にすると、
自社のウェブアプリ以外からのアクセスを弾ける。無料枠のまま可能。

## データモデルの変更点

Apps Script 版は運行中の状態を「進行中」シートに状態JSONで持っていたため、
管理者が手で直せず、取り消しや修正のたびに整合が崩れる余地があった。
Web版では運行そのものに `status: 'running' | 'done'` を持たせ、運行中と確定済みを
同じ形で扱う。運行中の記録も管理画面から普通に直せる。
